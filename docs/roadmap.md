## 方向一：浏览器快捷打开

### 现状
- 页签（chip）最左侧有一个 🌐，调用宿主 `ctx.sidebarRight.openTab('browser', { params: {} })`。
- 打开的是宿主浏览器的**空白起始页**（带地址栏）；`browser` kind 只在 desktop profile 挂载，web profile 没有。
- 失败时按钮变 `!`，原因写在 `title` 里，无其他提示。

### 待解决的问题（设计前要先定）
1. **去重行为**：宿主按 `(kind, address)` 去重，连续点 🌐 可能只是聚焦已有的空白页，而不是新开一个。
2. **入口位置**：宿主 tab 条右侧那簇（分栏/全屏/折叠）属于宿主 chrome，**没有插件插槽**，插件只能注入 chip 内部；已确认无法放到最右。
3. **没有"打开什么"的语义**：现在永远是空白页，用户还得自己输地址。

### 候选方案（按代价排序）
| 方案 | 做法 | 代价 / 风险 |
|---|---|---|
| A. 每次新开 | 给每次点击生成唯一 seed（如 `?dsh-new=<计数>` 之类的无害地址，或调用宿主 `browser.new` 命令） | 需要确认宿主 `openTab` 的去重键与 `multiple` 语义；伪地址可能被浏览器地址栏回显 |
| B. 打开"当前文件对应的网址" | 识别文件里的 URL（markdown 链接 / `.url` / `open-with` 目标），点击时带上 `url` | 需要先有"当前上下文 URL"的概念，价值取决于使用场景 |
| C. 默认首页可配 | 插件设置里填一个起始 URL，🌐 打开该地址 | 简单，但与"快捷"关系不大 |
| D. 快捷键 | 复用/注册一个快捷键（宿主已有 `browser.new` 命令，可查其 id 与默认键） | 与宿主原生快捷键可能冲突，需要探测 |

### 建议的验收
- 连续点 3 次 → 得到 3 个独立浏览器页签（或明确聚焦语义），行为稳定可预期。
- web profile 下按钮隐藏或给出明确不可用提示（现在只改 `!`）。

## 方向二：完善灵感模块

### 现状
- 根目录固定 `<workspace>/.dsh-whiteboard/`，不存在时自动创建。
- 直接复用上游 `FileTree`：**完整目录**（不限 `.md`），右键菜单与「文件」根完全一致（打开方式 / 在文件管理器中显示 / 复制路径 / 重命名 / 删除 / 上传 / 新建 / 引用到对话）。
- 「+ 新建灵感」自动命名 `灵感-YYYYMMDD-HHmm.md` 并打开。
- 已知取舍：因为复用文件树，非 Markdown 文件（图片、附件）也会出现在列表里。

### 待补的能力（按价值排序）
1. **只显示 Markdown（可选）**：给 `FileTree` 加 `onlyExtensions?: string[]`（客户端过滤或 host 侧过滤），默认关闭；开启后只列 `.md`，但可能让"上传附件"不可见。
2. **脑图联动**：约定这些 `.md` 就是 dsh-mindmap 的输入；若检测到该插件已安装，提供"用脑图打开"入口（通过 `ctx.betterSidebar.getTab('dsh-mindmap:mindmap')` 探测 + `openTab`）。
3. **模板 / 新建流程**：新建时可选模板（空白 / 会议 / 灵感卡片 / 问题清单），模板内容写在 `.dsh-whiteboard/.templates/`。
4. **检索与最近**：灵感列表顶部加搜索框（复用 `fs.search` 限定目录）；按最近修改排序；"最近打开的 3 篇"（`openPath` 已持久化，可扩成列表）。
5. **每日笔记**：`日记/YYYY-MM-DD.md` 一键打开/创建（类似 Obsidian daily note）。
6. **置顶 / 收藏**：在 `.dsh-whiteboard/.pins.json` 存路径列表，列表顶部固定；不污染文件本身。
7. **工作区卫生**：首次创建目录时提示（或自动写）`.dsh-whiteboard/.gitignore` + 说明，避免笔记进入 Git 变更噪音。
8. **可配置目录名**：插件设置项替换固定的 `.dsh-whiteboard`（默认值保持不变）。

### 需要先定的问题
- 灵感根是否**只允许 Markdown**？（影响 1、3、7 的实现）
- 是否把 dsh-mindmap 作为**可选依赖**接入，还是保持在"普通 Markdown 文件"层面互操作？
- 目录名/模板是否需要跟随会话 workspace 配置，还是全局统一？

### 建议的验收
- 灵感里新建/打开/重命名/删除与文件模块体验一致（已达成）。
- 开启"只显示 Markdown"后列表只剩 `.md`，且上传/新建仍可用。
- 装了 dsh-mindmap 时出现"用脑图打开"，未装时入口不出现（不是坏按钮）。
