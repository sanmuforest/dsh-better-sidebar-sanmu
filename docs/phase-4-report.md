# phase-4-report.md — 持久化、空状态与错误路径

> 2026-10-29 · 阶段四交付记录 · `dsh-better-sidebar-sanmu@0.1.0`

## 1. 持久化（按会话）

存储键：`localStorage['dsh-better-sidebar-sanmu:workbench:<sessionId>']`，每次变更即写；读取时逐字段校验，损坏的文档回落到默认值（不会白屏）。

| 状态 | 说明 |
|---|---|
| 四个 section 折叠 | `collapsed`，默认只展开「文件」 |
| 左侧栏宽度 | `leftWidth`；拖动/键盘调宽后保存，`ResizeObserver` 在面板变窄时把它夹回合法范围，避免右栏被挤成 0 |
| 文件树展开目录 | `expanded[]`，刷新后树木保持原样 |
| 最近打开的文件 | `openPath`：重载后直接恢复上次打开的文件（执行文件里标注为"可选"，这里用"恢复上次文件"实现，未做最近列表） |

## 2. 本轮新增

- **Ctrl/Cmd+S 全局保存**：焦点在编辑器外（左栏、头部按钮）也能保存；编辑器内的 `Mod-s` 已处理的事件不会二次保存（`defaultPrevented` 守卫）；**仅在当前 tab 可见时生效**（宿主会常驻挂载访问过的 tab，避免后台 tab 抢快捷键）。
- **空工作区提示**：根目录 0 条目时，树上方给出「工作区还是空的，用 + 文件 新建第一个文件」——树组件本身对空目录只画空白，这层提示补上操作入口。
- **保存失败可读化**：头部按钮标题在 `saveState=failed` 时写明"文件可能已在磁盘上被修改，请处理冲突后重试"；冲突横幅仍由上游编辑器渲染。

## 3. 错误与空状态清单

| 场景 | 现状 |
|---|---|
| 文件读取失败 | 右栏显示**完整路径 + 错误文本 + 重新读取**按钮 |
| 保存失败（mtime 冲突等） | 编辑器冲突横幅 + 头部"保存失败" + 悬停原因；未保存切换弹窗里保存失败会原地报错、不切换 |
| 新建文件/文件夹失败 | section 内红色错误条（服务端文案直出） |
| 上传失败 | 同上 |
| 灵感目录不存在 | 视为空状态，不报错；新建时自动创建 `.dsh-whiteboard` |
| 灵感为空 | 明确提示 + 「+ 新建灵感」入口 |
| 文件树为空（根） | 本轮新增提示 + 入口 |
| 任务 / Git 面板崩溃 | 外包 `RenderBoundary`，只坏这一节，其余照常 |
| 浏览器 kind 缺失 | chip 上的按钮变 `!`，`title` 给出原因 |
| 未打开文件 | 右栏空状态「从左侧选择文件开始编辑」 |

## 4. 与基线原功能的隔离

- 工作台只**新增一个 tab 类型**（`workbench`），不注册新路由、不新增服务、不改 `ctx.betterSidebar` 契约。
- 嵌入的 Git / 任务面板仍是上游组件，各自持有自己的轮询与 store 读写，工作台只是提供宿主与尺寸。
- 唯一影响面：`FileTree` 的 chevron/引导线是共享组件改动，因此原生「文件」页也会同步变样（有意为之，保持两处观感一致）。
- 其它页签（文件 / Git / 任务 / 侧边对话 / 浏览器 / 终端）不受影响；卸载插件时随原生 tab 类型一起消失。

## 6. 验收步骤（Ctrl+Shift+R，必要时重启）

1. 折叠「灵感/任务/Git」，把左栏拖宽，打开一个文件 → 刷新页面：三个状态应全部恢复（含上次打开的文件）。
2. 找一个空目录/空工作区看提示；灵感目录清空后看提示。
3. 把一个已打开文件在外部删除，再点「保存」→ 应看到冲突提示而不是静默。
4. 焦点放到左栏后按 Ctrl+S → 应保存当前文件。
5. 打开原生「文件」「Git」「任务」「浏览器」各页签，确认互不影响。
